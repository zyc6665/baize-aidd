# 精选与校准

「白泽智药」的精选只回答一个问题：这条消息对做 AI 药物研发的人值不值得花时间。判断标准在 `industry/prompts/selection-score.md`，入选门槛在 `industry/selection.ts`：前者说「什么算重要」，后者说「多少分算入选」。分开的好处是改标准不用碰数字，调数字不用重写提示词。

## 一条资料怎么变成精选

1. **收进来**：同一网址、同一内容只留一份；普通文章只有标题或摘要时，按信源规则补取正文。没有可信发布时间的资料先不公开。
2. **预筛**（`prefilter.md`）：是不是 AIDD 行业的事。宽进，只拦明显无关的（消费级硬件、通用办公软件、与药企无关的编程教程）；`BLOCK` 不出现在任何公开页面，`PASS` 和拿不准的 `UNKNOWN` 继续走。
3. **评分**（`selection-score.md`）：同一份标准独立打两次分（0–100），**两次之和 ≥ 2 × 门槛**才算够分，门槛按信源分级不同。页面上显示的是两次的平均分（向下取整）。
4. **结构化**（`structure.md`）：和评分同时进行。给出分类、标签、主体公司（药企、Biotech、CRO、模型与工具厂商），判断是一条具体新闻、讲多件事的综合稿，还是材料不够；具体新闻抽出事实（谁、做了什么、对什么、什么条件）和原文出处。主题页、事件归组和日报都靠它。
5. **写标题摘要**：入选的，以及平均分高于 `understandFloor` 的落选资料，按 `content-understanding.md` 写中文标题、答案先行的摘要和推荐理由；其余按 `summarize-*.md` 写短摘要进「全部动态」。浏览「全部动态」只出平均分不低于 `browseFloor` 的资料，没评上分的照常出；带搜索词时仍搜全部。
6. **归组去重**（`group-*.md`）：不同来源报道的同一件事归成一个事件，事件页有综述（`story-digest.md`），「热门」按事件排。够分的资料要等归组完成才进精选：模型同时判断它和已选报道是不是同一条新闻，以及有没有精选还没给过的具体信息。同一件事的多篇都值得选时，网页折成一个阅读组，API、RSS 和 MCP 每条新闻只出一条，代表报道按「官方一手 → 核实过的官方账号 → 有全文、分数高、发得早」挑。
7. **日报、周报、月报**：每天 08:00 的日报按规则编排，不调用模型；周报（周一 10:00）和月报（每月 1 日 10:30）由日报汇编，模型只写总述和栏目导读，不增删条目（`report-period.md`、`report-period-sections.md`）。出刊时间在 `site/site.ts` 的 `EDITION_TIMES`。

每一步的提示词都在 `industry/prompts/`，改提示词不用改代码；提示词版本就是它内容的哈希，改了只影响之后的新资料，判过的不重算。

## 门槛：`industry/selection.ts`

```ts
export const SELECTION = {
  thresholds: { T1: 36, T1_5: 38, T2: 40 },   // 两次评分的平均至少要到这个数
  classes: {
    vendor: { label: "厂商技术博客", threshold: 39 },
    ir: { label: "财报与投资者关系", threshold: 44 },
    leaderboard: { label: "评测榜单", threshold: 48 },
  },
  understandFloor: 35,
  browseFloor: 25,
};
```

分级：`T1` 官方一手（药企与 Biotech 官网、官方博客、监管机构、期刊与预印本），`T1_5` 官方账号与准官方创作者，`T2` 媒体与个人。官方门槛低于媒体（36 ≤ 38 ≤ 40）：一个模型的权重、一次临床读出、一份指南草案，通常只有发布方自己那条消息说得准，媒体转述容易丢掉关键数字。排序交给分数、事件热度和时间，不靠抬高门槛来筛。

媒体门槛只能比官方高，不能比官方低。倒挂等于「二手转述比原文更容易入选」，公开出口的权威排序和编辑模型都对不上，按这套分级校准出来的结论也不再成立。这一条也限制了 T2 的召回：评测里 T2 放到 36 能到 0.80，但那样媒体就比官方容易入选，所以不做。

类别只抬不降：有些官方源的日常内容主要写给自己客户或投资人，读者只看其中的大事，就在后台「信源」页给它选 class——`vendor` 厂商技术博客、`ir` 财报与投资者关系、`leaderboard` 评测榜单。实际门槛取分级门槛和类别门槛里高的那个，分级本来就更高的媒体不受影响。class 的 key 存在信源上，上线后不要改名，改了的类别会悄悄失效。评测样本不带类别，只按分级门槛算。

`understandFloor` 决定落选资料用哪种写法，`browseFloor` 决定什么能进「全部动态」；设成 `0` 就列出全部公开资料。

## 校准

### 1. 样本集

`industry/gold.jsonl` 是本站的人工标注集，现有 28 条：17 条该选（`select`）、11 条不该选（`reject`），全部标成 `benchmarkSplit: "development"`。每行一条：

```json
{"caseId":"aidd-012","material":{"title":"原文标题","originalTitle":null,"publishedAt":"2026-10-14T09:00:00+08:00","sourceName":"信源名称","bodyZh":null,"bodyOriginal":"正文……"},"sourceFacts":{"sourceKind":"rss","sourceTier":"T1","firstParty":true,"language":"zh"},"samplingContext":{"benchmarkSplit":"development","samplingStratum":"clinical"},"gold":{"decision":"select"}}
```

字段：`caseId` 唯一；`material` 放标题、原标题、发布时间、信源名和正文（中文放 `bodyZh`，原文放 `bodyOriginal`，有一个就行）；`sourceFacts` 放信源类型、分级、是否一手和语言，分级决定用哪个门槛；`samplingContext` 可选，`samplingStratum` 用来分组看错在哪一类（`clinical` 临床、`deals` 交易、`policy` 监管、`models` 模型与工具）；`gold.decision` 是 `select`、`reject` 或 `either`（两可，不计入准确率）。

多放难例（差一点就该选、差一点就不该选），否则准确率虚高；留一部分标成 `holdout`，调提示词只看开发集。标注的人最好就是以后读这个站的人。评测只跑预筛和两次评分，不含归组去重，所以按「这条本身该不该选」标，不要因为同一件事已经选过另一篇就标 `reject`。

### 2. 跑评测

```bash
node --env-file=.env scripts/eval-selection.ts --gold industry/gold.jsonl --label "第一版"
```

对每条样本跑一遍预筛和两次评分，输出有效输出准确率、查准率（P）、查全率（R）、F1，以及覆盖率、完整准确率（把失败也算没做对）和一张门槛扫描表。判错的条目写到 `.data/eval/`，同时导入后台 SelectBench（加 `--no-import` 不导入）。

不传 `--models` 时用「精选评分」这一步线上正在用的模型；`--models default,deepseek-flash` 可以在同一批样本上比几个。其他参数：`--n` 抽样条数、`--split holdout` 只跑留出集、`--concurrency` 并发数。`site/site.ts` 的 `DEPLOYMENT.selectionGold` 可以固定样本文件、抽样条数、用哪一份和门槛扫描范围，不给就用 `.data/gold.jsonl` 和 40–90。注意扫描表默认从 40 起，现在的 T1 36、T1_5 38 不在表里，想比较这两档要把 `sweep` 往下调。

同一次评测里渲染出相同输入的样本共享评分结果，重复运行复用回执（不重复花钱）；报告里的 token 和耗时是回执累计值，不代表这次的新增费用。

`npm run check:gold` 只查 `industry/gold.jsonl` 的格式（`caseId` 不重复、标题和正文非空、`decision` 合法），不调模型也不连库，CI 每次都跑。

### 3. 看错例，改标准，再跑

在后台 SelectBench 里逐条看判错的资料和模型给的理由：该选没选，多半是 `selection-score.md` 没写清这类价值，把它写进「必须正常评价」并给例子；不该选却选上，多半是噪声没压住，写进「必须压住」；整体偏松或偏紧、错例又都贴着门槛，才动 `industry/selection.ts` 的数字。先改标准再动门槛——门槛只能整体平移，解决不了「哪一类判错了」。

比较模型别只看有效输出 F1：覆盖率差得多时一起看完整准确率，高分但经常答不出结构化结果的模型，不该被失败样本从分母里藏掉。

改门槛之后：门槛只在分析资料时读一次，已入库的 `analyses.selected` 不会自动变，而公开内容读的正是这个字段。要让已发布内容跟着新门槛走，得按新门槛重算这些记录的 `selected`，再逐条重新发布（`publishArticle`）；没有现成的一键脚本。只让新门槛影响之后的新资料，通常更省事。

## 历史结论

2026-11 第一次校准前用的是 50 / 55 / 65。那时评分模型的分布已经很压缩：真事集中在 40–60，噪声在 12–30，很少给到 70 以上。按旧门槛跑，整体 recall 只有 0.263，19 条该收的漏了 14 条，T1 召回只有 26%——官方一手的重要消息大多进不了精选。压到 36 / 38 / 40 后，T1 召回 100%、T1_5 召回 100%，代价是 T2 召回约 70%；放到 40 附近整体 F1 到 0.80。换模型或改评分提示词后分数区间可能整体平移，必须重跑评测再定数字。

## 换模型

后台「模型与评测」页能看到每一步当前用哪个模型、近期成功率、耗时和 token 用量，也能直接切换（只影响之后的新任务）。换评分模型之前，先用 `--models` 在同一批样本上比一比。
